# 🧩 Агент-оркестратор

**Назначение:** координация и маршрутизация запросов между тулзами и агентами (RAG, GenUI, поиск недвижимости).  
**Технологии:** LangGraph, FastAPI, MemorySaver (PostgresSaver чуть позже), асинхронные вызовы.

---

## 🧠 Описание

Агент-оркестратор — это **центральный узел** мультиагентной системы `globrix-llm-basic`. Он:

- принимает запросы от пользователя (через FastAPI),
- анализирует их на предмет задачи (поиск недвижимости, генерация лэндинга, вопросы о районе),
- вызывает соответствующие **тулзы** (например, `realty_search`, `regional_rag_tool`, `genui_tool`),
- сохраняет состояние диалога (с помощью чекпоинтера),
- возвращает результат пользователю.

---

## 🚀 Особенности реализации

- **Класс-агрегатор:** `OrchestratorAgent` управляет графом и чекпоинтером.
- **Асинхронная архитектура:** `ainvoke`, `async def`, `lifespan`.
- **Интеграция с FastAPI:** через `app.state.agent`.
- **Чекпоинтер:** `MemorySaver` (готов к замене на `PostgresSaver`).
- **Маршрутизация:** на основе ключевых слов в сообщении.

---

## 🛠️ Используемые тулзы

| Тул | Назначение | Ответственный |
|-----|------------|---------------|
| `realty_search` | Поиск объектов недвижимости по фильтрам | Анна |
| `regional_rag_tool` | Ответы на вопросы о регионе | Юлия (обёртка) |
| `genui_tool` | Генерация лэндингов | Сергей (обёртка) |

---

## 🧪 Пример работы

1. Пользователь: *"Найди 2-комнатную квартиру в центре."*
2. Оркестратор:
   - распознаёт задачу → вызывает `realty_search`
   - получает результат → возвращает пользователю
3. Пользователь: *"Сделай лэндинг."*
4. Оркестратор:
   - вызывает `genui_tool`
   - получает HTML → возвращает пользователю

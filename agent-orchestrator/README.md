# 🧩 Агент-оркестратор

**Назначение:** координация и маршрутизация запросов между тулзами и агентами (RAG, GenUI, поиск апартаментов).  
**Технологии:** LangGraph, FastAPI, MemorySaver, асинхронные вызовы.

---

## 🧠 Описание

Агент-оркестратор — это **центральный узел** мультиагентной системы `globrix-llm-basic`. Он:

- принимает запросы от пользователя (через FastAPI),
- анализирует их на предмет задачи (поиск апартаментов, генерация лэндинга, вопросы о районе),
- вызывает соответствующие **тулзы** (например, `apartments_search`, `regional_rag_tool`, `genui_tool`),
- сохраняет состояние диалога (с помощью чекпоинтера),
- возвращает результат пользователю.

---

## 🚀 Особенности реализации

- **Класс-агрегатор:** `OrchestratorAgent` управляет графом и чекпоинтером.
- **Асинхронная архитектура:** `ainvoke`, `async def`, `lifespan`.
- **Интеграция с FastAPI:** через `app.state.agent`.
- **Чекпоинтер:** `MemorySaver` (готов к замене на `PostgresSaver`).
- **Маршрутизация:** на основе ключевых слов в сообщении.
- **Поддержка тулзов коллег:** через `services/core_api_client`.

## 🛠️ Используемые тулзы

| Тул | Назначение | Ответственный |
|-----|------------|---------------|
| `apartments_search` | Поиск апартаментов по фильтрам (через API Сергея) | Анна |
| `regional_rag_tool` | Ответы на вопросы о регионе | Юля (обёртка) |
| `genui_tool` | Генерация лэндингов | Сергей (обёртка) |

---

## 🧪 Пример работы

1. Пользователь: *"Найди 2-комнатные апартаменты, доступные для покупки."*
2. Оркестратор:
   - распознаёт задачу → вызывает `apartments_search`
   - получает результат → возвращает пользователю
3. Пользователь: *"Сделай лэндинг."*
4. Оркестратор:
   - вызывает `genui_tool`
   - получает HTML → возвращает пользователю
